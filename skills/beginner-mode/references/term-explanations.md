# 技术词短解释参考

仅在需要解释相关词、检查措辞或区分概念时阅读对应部分。不每轮完整加载或照搬给用户；不是频率榜或穷尽词表。表中未列出的专业词也应按当前任务主动解释，不能等用户追问。正式名称保留，一般先讲用途，不先给英文全称或一串新术语。具体工具的行为和限制以当前环境及官方说明为准。

## 文件与配置

| 词 | 可用的短解释 | 容易误解的边界 |
|---|---|---|
| HTML / `.html` | HTML 是描述网页内容和结构的写法；`.html` 是常见网页文件后缀，可用浏览器打开。 | 能打开文件不等于所有功能都能离线使用，仍要看是否依赖网络服务。 |
| `.md` / Markdown | 一种文本文件格式，用简单符号表示标题、列表和链接，常用来写说明。 | 可以用文本编辑器打开；它不是某一种 AI 专用文件。 |
| `README.md` | 项目的说明文件，通常介绍用途和使用方法。 | 内容应实际阅读，不能仅凭文件名猜项目能力。 |
| `SKILL.md` | 给 AI 的一份技能说明，告诉它何时、怎样处理某类任务。 | 文件存在不等于当前工具已加载它。 |
| `AGENTS.md` | 某些 AI 编程工具读取的项目工作说明，例如修改代码时应遵守哪些约定。 | 是否读取及适用范围取决于工具和文件位置。 |
| JSON / `.json` | 按固定格式保存数据的文本，例如 `{"城市":"京都","天数":3}`，方便程序读取。 | 可用于设置或备份；改动时要保持格式正确，不是普通的随意记事文本，也不是一种需要安装的软件。 |
| YAML / `.yaml` | 常用来写配置的文本格式，通过缩进表达层次。 | 缩进可能影响含义。 |
| 环境变量 / `.env` | 环境变量是程序运行时读取的设置；`.env` 常用来存放这些设置。 | `.env` 不会在所有程序里自动生效；也不等于加密文件。 |

## 网页与界面

| 词 | 可用的短解释 | 容易误解的边界 |
|---|---|---|
| CSS | 控制网页颜色、字体、间距和排列的样式规则。 | 主要处理呈现方式；网页内容结构由 HTML 描述。 |
| JavaScript / JS | 常用来让网页响应操作、处理数据的编程语言，例如点击后更新列表。 | 也能在浏览器之外运行；与 Java 是不同语言。 |
| 组件 / Component | 界面中可单独组织和重复使用的一块，例如搜索框或商品卡片。 | 不一定是安装来的插件，也不一定只对应一个按钮。 |
| 状态 / State | 程序为当前界面记住的信息，例如选中了哪一项、是否正在保存。 | 记在当前界面里不等于已经长期保存，刷新后能否保留取决于实现。 |
| 内边距 / Padding | 文字或图片与所在方框边缘之间的空隙。 | 调整的是方框内部留白，不是两个方框之间的距离。 |
| 外边距 / Margin | 方框外侧的留白，用来调整它与周围内容的距离。 | 两块内容之间的空隙也可能来自其他布局设置，不能只看外观就认定是外边距。 |
| 响应式设计 / Responsive Design | 让页面根据屏幕空间调整排列和大小，便于在手机、电脑上使用。 | 不是把整个电脑页面等比例缩小；文字和按钮也要能看清、操作。 |
| 轻提示 / Toast | 操作后短暂出现的消息，例如“已保存”，通常不打断当前操作。 | 需要用户处理的失败原因不能只靠一闪而过的提示。 |
| 文字提示 / Tooltip | 鼠标停留或键盘移到图标、按钮上时出现的简短说明。 | 通常不是放操作按钮的窗口；关键说明不能只靠鼠标悬停才能看到。 |
| 模态弹窗 / Modal | 弹出后需要先处理或关闭，才能继续操作后面页面的窗口。 | 不是所有浮在页面上的提示都属于模态弹窗。 |
| 抽屉面板 / Drawer | 从页面边缘展开的一块面板，常用来放菜单、详情或编辑内容。 | 是否挡住页面其他操作取决于设计，不一定具有模态弹窗的行为。 |
| 骨架屏 / Skeleton | 内容加载前，先用简单形状占住文字、图片等预计出现的位置。 | 只是等待时的占位显示，不代表内容已加载，也不会自动让数据加载变快。 |
| 悬停 / Hover | 鼠标指针停在某个元素上，还没有点击。 | 触屏设备不一定有同样的操作方式，必要功能不能只靠悬停触发。 |
| 焦点 / Focus | 当前准备接收键盘输入或操作的对象，例如正在输入的文本框。 | 不等于鼠标正停在哪里；键盘也能移动焦点。 |

## 项目与版本管理

| 词 | 可用的短解释 | 容易误解的边界 |
|---|---|---|
| MIT 许可证 | 一种允许使用、修改和商用的代码使用规则；分发副本或主要代码时需保留版权及许可声明。 | 不是毫无限制的“随便用”；软件按现状提供，不作担保。 |
| Git | 记录文件修改历史的工具，便于比较修改和恢复已记录的版本。 | 没记录或没保留的内容不保证能恢复。 |
| GitHub | 存放、分享代码项目的网站，也方便多人合作。 | 不同于 Git；公开可见不等于可以任意复用。 |
| 仓库 / Repository | 保存项目文件和版本记录的地方，可以在本机，也可以在网上。 | 不一定指 GitHub 上的项目。 |
| 分支 / Branch | 同一项目的一条修改路线，便于单独开发某个功能。 | 不等于另一个文件夹。 |
| 工作树 / Worktree | 实际放着可编辑项目文件的目录；额外工作树让同一项目的不同版本可同时在不同目录里修改。 | 共享 Git 仓库记录，不是独立备份或安全隔离环境；新建分支不一定新建工作树。 |
| 克隆 / Clone | 把一个 Git 项目及其版本记录复制到本机。 | 下载完成不等于安装完成或能直接运行。 |
| 暂存区 / Staging Area | Git 中准备放进下一次提交的内容，可以先挑选这次要记录的修改。 | 暂存不等于提交或上传；暂存后继续改文件，新改动也需要再选入才会进入这次提交。 |
| 提交 / Commit | 把一组修改记录成一个可追溯的版本。 | 通常先记录在本机，不等于上传。 |
| 推送 / Push | 把本机的版本记录发送到远程仓库。 | 不自动等于网站已上线。 |
| 差异 / Diff | 显示文件具体增加、删除或修改了哪些内容的对照。 | 是修改对照，不是运行结果。 |
| PR / Pull Request | 在 GitHub 等平台提出合并修改的请求，方便先查看和讨论。 | 创建请求不等于已经合并。 |

## AI 的工作方式

| 词 | 可用的短解释 | 容易误解的边界 |
|---|---|---|
| 大模型 / LLM | 根据输入理解和生成语言等内容的 AI 模型。 | 流畅回答不代表事实正确或已经执行操作。 |
| 提示词 / Prompt | 你给 AI 的要求和参考信息。 | 不要求写特殊咒语；正常说清目标即可。 |
| 系统提示词 / System Prompt | 产品或应用给模型的行为要求和背景信息，例如回答方式、工作范围。 | 具体设置方式取决于产品；写下指令不等于获得文件访问权或绕过实际权限检查。 |
| 上下文 / Context | AI 这次回答时能够参考的对话、文件和其他信息。 | 不等于它能读取所有文件或记住过去全部聊天。 |
| 上下文窗口 | 模型一次能处理的信息容量。 | 容量有限，不能据此保证每处细节都被准确利用。 |
| 上下文压缩 | 把较长的历史整理成较短摘要，以便继续工作。 | 摘要可能遗漏细节；不等于删除项目文件。 |
| Token | 模型计算输入输出长度时使用的文本单位，可能是一字、一个词或词的一部分。 | 不固定等于一个汉字或英文单词。 |
| Agent / 智能体 | 能围绕任务调用工具、分步执行工作的 AI 助手。 | 能做什么取决于接入的工具和权限。 |
| Skill / 技能 | 给 AI 的一套任务做法，通常由说明和辅助文件组成。 | 不会凭空提供宿主没有的工具、账号或权限。 |
| 工具调用 | AI 实际使用搜索、读文件等工具执行操作。 | 说“我会搜索”不等于已经搜索。 |
| API | 软件提供给其他程序调用功能或交换数据的入口。 | 有入口不代表无需账号、权限或费用。 |
| MCP | 让 AI 应用按统一规则连接外部工具和数据的标准。 | 不是模型本身，也不代表自动获得所有访问权限。 |
| RAG | 先检索相关资料，再让 AI 参考资料回答的方法。 | 能补充依据，但不保证每次答对。 |

## 运行与交付

| 词 | 可用的短解释 | 容易误解的边界 |
|---|---|---|
| 终端 / Terminal | 通过输入命令操作电脑的窗口。 | 使用哪种命令要看系统和当前目录。 |
| 依赖 / Dependency | 项目运行或制作时需要的其他软件包。 | 安装依赖不等于项目已完成。 |
| 运行环境 | 程序运行所需的软件及版本组合。 | 相同代码在不同环境里可能表现不同。 |
| 前端 / 后端 | 前端是用户看到并操作的部分，后端是在另一端处理请求和数据的程序。 | 简单网页可以没有独立后端。 |
| 构建 / Build | 把项目代码处理成准备运行或发布的文件。 | 构建成功不等于所有功能都测过。 |
| 部署 / Deploy | 把程序放到目标环境并配置好，让它能运行和被访问。 | 是否公开、谁能访问，要看部署位置和设置。 |
| 静态网站 | 主要向浏览器提供现成网页、样式和脚本文件的网站，也可以有浏览器内的交互。 | 静态不等于不能点击；它本身不自动提供登录、共享数据库等服务器功能。 |
| Cloudflare Pages | 托管网页并提供访问网址的平台，可按实际项目选择直接上传或关联代码仓库发布。 | 能否完整运行要看项目依赖；有网址不等于不同设备数据会同步，使用条件以当前官方说明为准。 |
| GitHub Pages | 从 GitHub 仓库发布静态网站的服务。 | 仅上传代码不等于启用发布；不是任意服务器程序的运行平台。 |
| 本地 / localhost | 在当前这台设备上；`localhost` 地址指向访问它的设备自己。 | 发给朋友相同地址，不会让他打开你的电脑。 |
| API Key / 密钥 | 程序调用某个服务时使用的身份凭证。 | 不是普通链接；不要把真实值放进公开说明或代码。 |
| 沙箱 / Sandbox | 对程序可访问的文件、网络或操作范围加以限制的运行环境。 | 限制范围需实际确认，不等于绝对安全。 |

## 身份与权限

| 词 | 可用的短解释 | 容易误解的边界 |
|---|---|---|
| 身份认证 / Authentication | 核验现在使用服务的是谁，例如通过密码或验证码确认登录身份。 | 登录成功不代表可以查看或修改所有内容。 |
| 权限控制 / Authorization | 判断当前使用者能查看、修改或删除哪些具体内容。 | 仅隐藏按钮不能替代实际权限检查；能看到入口也不代表已获准操作。 |

## 校验与效果评估

| 词 | 可用的短解释 | 容易误解的边界 |
|---|---|---|
| SHA-256 | 给文件或文本计算一串固定长度“内容指纹”的方法，常用于核对内容是否改变。 | 不是给文件加密；数值相同也不能证明文件安全或来源可信。 |
| 哈希 / Hash | 把内容按规则计算成一个较短的值，方便比较或查找。 | 不同算法用途不同，不保证永不重复。SHA-256 是其中一种算法。 |
| 校验和 / Checksum | 根据数据算出的核对值，常用来检查传输或保存时有没有出错。 | 不把所有校验方法都当成安全验证。 |
| Benchmark / 基准测试 | 用约定的任务和评分方法比较软件或模型的表现。 | 分数受题目和测试条件影响，不等于实际使用一定更好。 |
| Eval / 评测 | 用具体任务和判断标准检查 AI 的表现。 | 可以是自己的测试；不一定是公开榜单或统一标准。 |
| 测试集 | 专门用来检查效果的一组题目或样本。 | 少量样本不能代表所有使用场景。 |
| Baseline / 基线 | 用来比较新方案是否更好的原有或基础方案。 | 不一定是最低标准，也不一定是最强方案。 |
| A/B 测试 | 在可比较条件下测试两个版本，看哪个更符合目标。 | 随意各问一次不能保证有可靠结论。 |
| 回归测试 | 修改后重新检查原有功能，确认没有把之前能用的部分改坏。 | 只覆盖实际检查的范围。 |
| 延迟 / Latency | 发出请求到某个结果出现所等待的时间。 | 应说清指首个响应还是完整结果。 |
| 吞吐量 / Throughput | 一定时间内系统能处理或输出多少内容。 | 不等于单次等待时间，也不等于答案质量。 |

遇到陌生产品名和缩写，先核对具体来源，再说明用途。例如“Jev benchmark”可能是在说某个 Jev 系统的评测或某个项目名；不能仅凭几个字认定用户指哪个项目，也不能当作通用术语硬编定义。只需解释通用的 benchmark 时，无须展开无关产品调研。

## 从用户的大白话接到当前任务

先理解用户要的效果；术语有助于消除歧义或后续交流时，再顺带命名。不要求用户先学会术语或把需求重新发一遍。下面是原创回应示例，不是固定输出格式，也不代表已执行这些修改；最终报告仍须依据实际操作和验证。

| 用户大白话 | 合适概念 | 任务中一句回应 |
|---|---|---|
| “这个输入框的字快贴到边上了，留点空。” | 内边距 | 我会增加输入框的内边距，也就是文字与框边之间的空隙，再检查窄屏上是否仍放得下。 |
| “收藏点了像没反应，让我知道成功了。” | 状态反馈、轻提示 | 我会在确认收藏成功后显示“已收藏”的轻提示（一条短暂出现的结果消息），并让收藏按钮显示已选中状态。 |
| “同事已经登录，怎么还打不开我分享的项目？” | 身份认证与权限控制 | 登录确认他是谁，权限决定他能打开哪个项目；我会先检查分享范围和所用账号，再定位打不开的原因。 |

这些示例只展示任务中的一句回应；本轮新解释的词仍按主技能要求收入“本次名词积累”。
