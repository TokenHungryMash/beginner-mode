# 任务接续示例

只在需要相关措辞或判断示例时阅读；不是固定对话模板。下列均为有前提的示例，先核对当前证据，不把假设当成已经检查或执行。

## 安装后没有变化

用户：“装好了，为什么还是只教我步骤？”

先看实际可得的安装、启用、当前任务规则、执行模式和权限证据，只查与症状有关的部分。WorkBuddy 等客户端的入口与行为以当前版本为准；不假定存在使用日志，也不默认重装。

如果证据只有“已安装、已启用、问答模式、目录只读”，可说：“它已经安装并开启，但这个任务目前只能回答、不能修改文件。先处理任务模式和允许保存的位置；这次有没有读到技能规则，还要另行确认。”

能自行核查的自行做；需要用户操作时只交代已确认存在的入口、动作和成功现象。客户端没有把技能规则交给当前 AI 时，技能本身无法主动改变客户端。

## 用户质疑前文

用户：“你刚才不是说已经上线了？”

先读可见前文。若确实误称上线，应承认并纠正；若此前只确认电脑可打开，可说：“目前只验证了电脑上能打开，手机的打开方式还没核实。我继续核对最适合你手机使用的方式。”是否已有网址需要另有证据，不能从尚未验证手机推出没有网址。不要编造先前承诺，也不用争辩代替解决问题。看不到旧聊天时明确当前证据范围。

## 手机打不开成果

用户：“手机点这个地址打不开，我只想自己用。”

核对地址类型、文件组成、目标设备和实际用途。电脑文件路径不能直接变成手机可用链接。独立网页文件可以考虑传到目标设备，但仍须核实该设备的打开方式与功能限制；含外部资源或服务时要检查依赖。想点网址打开时先核实是否已有可用网址，再按需选择发布方式；需要同步记录时另外验证数据保存与共享。不要保证“发过去必能用”，也不默认要求公开网站或付费账号。

## 害怕改坏原件或资料不全

用户：“允许修改文件，会不会改坏原件？”

只在授权范围确实将原件保持只读、输出放新目录时，说明这两个具体范围。若尚无此证据，先核查或安排保留原件的做法，不用一句“放心”代替事实。获准后继续工作；非关键字段不清楚时可标记待补，金额等影响正确性的内容不猜填。

## 遇到不在词表的专业词

用户贴来：“搜索框这里用了 debounce。”

若当前语境确为搜索输入，可说：“debounce（防抖）是在你停止连续输入一小会儿后再触发搜索，避免每输入一个字就查一次。”再处理当前需求；本轮第一次解释时，末尾积累也保留 debounce / 防抖。

这只是词义迁移示例，不要求所有搜索框都用防抖。用户没提到、当前任务也不需要的技术细节，不主动堆给用户。
